## Q1 · 运动与活动水平的双重计算

**背景**：用户选「高度活跃」（系数 1.725）又手动记录跑步 5 公里 → 运动被算两次，净摄入被严重低估，App 会误报「缺口过大」。

| 选项 | 做法 |
|---|---|
| **A（默认）** | 把「活动水平」显式重定义为**除刻意锻炼外的日常活动量**，设置页加引导文案 |
| B | 运动数据满 7 天后，自动把活动系数降为「久坐 + 日均运动消耗」动态算 TDEE（更准，但 RDI 会随运动抖动，与「不对单日过度反应」冲突） |
| **C（默认叠加）** | 检测到活动水平 ≥ 高度 **且** 近 7 天有规律运动记录时，设置页顶部显示提示条 |

## Q11 · 追认：RDI 不含运动回加

已在 PRD v1.1 中作为「关键设计决策 1」执行：
- RDI 由 `BMR × 日常活动系数 × 目标系数` 计算，**与当日运动记录无关**；
- 运动消耗只出现在 `DailyEnergyBalance`，用于描述「今天是盈余还是缺口」；
- 目的：杜绝「跑了 5 公里所以能吃回去」的补偿性进食诱导。

## 已确认决策（归档，不再讨论）

| 项 | 结论 |
|---|---|
| 记录范围 | 可配置进食时段 + 随手记时间轴 + 饮水/运动/补充剂/身体数据（三项全选） |
| 默认时段 | 早餐 / 午餐 / 晚餐 / 上午加餐 / 下午加餐 / 夜宵 / 饮品（7 个，可增删改名） |
| 分析阈值 | 偏低 < 70% RDI，偏高 > 130% RDI，可配置 |
| 微量判定 | 用 7 天均值，且**完全不受运动影响**（双通道隔离） |
| 建议文案 | 内置黑名单 guard，禁止补偿性进食表述 |
| 数据管理 | 设置页提供导出 JSON + 清空数据 |
| 主题 | 冷灰数据极简；近白背景 / 石墨黑文字 / 冷蓝唯一强调色 / 中等圆角 / 0.5px 细边框 / 零阴影 |
