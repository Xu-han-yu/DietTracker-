# DietTracker PRD（MVP v1.1）

> 定位：一个**完全离线可用**的中文饮食与营养记录 App。用户在 App 内用自然语言记录「吃了什么、喝了什么、动了多久」，App 本地解析 → 本地营养表 / MET 表查询 → 对比个人推荐摄入量 → 输出**基于最近 7 天趋势**的中文建议。
> 所有分析在设备端完成，不依赖网络，不上传任何数据。

## 1. 目标与非目标

**目标**
- 记录门槛低到「一句话就能记」，不强制填表。
- 所有记录都能产出可用的营养结论：热量、蛋白质、脂肪、碳水 + 钙、铁、维生素 C、膳食纤维（4 项微量全覆盖）。
- 运动消耗本地估算，与饮食合并为**净能量平衡**。
- 建议是「明天怎么做」而非「今天你完了」。

**非目标（MVP 不做）**
- 账号/云同步、社交、拍照识别食物、条码扫描、大模型联网解析、医疗诊断。
- **HealthKit / GPS / 心率 / Apple Watch / 任何运动 API** —— 运动数据纯手动输入 + 本地估算。

## 2. 信息架构（4 个 Tab）

```
TabView
├── 今日 Today      → TodayView      饮食记录 + 运动记录 + 净能量摘要
├── 历史 History    → HistoryView    按日回溯、编辑、删除
├── 趋势 Trends     → TrendView      能量三条曲线 + 营养素达标率
└── 设置 Settings   → SettingsView   个人档案、目标、时段、阈值、外部 API
```

### 今日 TodayView
**职责**：一天的主操作台。
- 顶部：日期 + **净能量平衡卡**（摄入 kcal / 运动消耗 kcal / 净摄入 kcal + 状态色条）。
- 进度环：热量 / 蛋白质 / 膳食纤维。
- **饮食区**：按时段分组的记录流（早餐 / 午餐 / 晚餐 / 上午加餐 / 下午加餐 / 夜宵 / 饮品），每组显示条目 + 小计热量，支持展开收起。
  - 入口 1：**时段输入** —— 自然语言 → 解析预览 → 确认入库。
  - 入口 2：**随手记** —— 常驻输入框 + 时间戳，按记录时间就近归入时段，也可选「不归类」。
- **今日运动卡片（新增）**：
  - 自然语言输入，例：「跑步 30 分钟」「快走 1 小时」「力量训练 40 分钟」「游泳 45 分钟」。
  - 解析预览行：运动类型 · 时长 · **强度标签（默认中等，可切换低/中/高）** · 估算消耗。
  - 已记录运动列表：可改强度（消耗实时重算）、可删除。
  - 每次估算旁显示「估算」字样。
- 快捷区：饮水（+200ml）、补充剂、体重记录。
- 底部：**「分析今天」按钮** → 生成/刷新当日分析摘要卡。

### 历史 HistoryView
**职责**：回溯与纠错。
- 按日分组列表：总热量、运动消耗、净摄入、记录条数、达标状态小圆点。
- 日详情：饮食 + 运动 + 非饮食条目均可编辑/删除；可补记漏填时段；运动条目可改时长与强度。
- 支持搜索食物与运动名称。
- 顶部提供「重新分析该日」。

### 趋势 TrendView
**职责**：看趋势而非看单日。
- 7 天（默认）/ 30 天切换。
- **能量三条曲线（新增）**：摄入 kcal / 运动消耗 kcal / 净摄入 kcal 叠加显示。
- 宏量营养素：蛋白质、脂肪、碳水曲线。
- 微量营养素 7 天均值 vs 推荐值横向对比条（钙 / 铁 / 维C / 纤维）。
- **7 天趋势结论卡**：持续偏低项、持续偏高项、能量趋势（上升/平稳/下降）、运动频率与平均消耗。
- 饮水、体重的独立小图。

### 设置 SettingsView
**职责**：让推荐值和判定规则「属于用户自己」。
- **个人档案**：性别、年龄、身高（cm）、**体重（kg，用于 MET 消耗计算，必填）**、体脂率（选填）。
  - 体重旁需提示：「用于估算运动消耗，建议定期更新」。
- **活动水平**：久坐 / 轻度 / 中度 / 高度 / 极高（5 档系数）。
  - **文案约束**：明确说明该系数**代表除刻意锻炼外的日常活动量**，避免与运动记录双重计算。
- **目标**：维持 / 减脂（−20%）/ 增肌（+10%），可微调百分比。
- **实时预览**：BMR / TDEE / 目标热量 / 三大营养素分配 / 微量参考值 + 公式来源说明。
- **进食时段管理**：增删时段、改名、调整时间区间与图标；随手记自动归类开关。
- **分析阈值**：偏低线（默认 70%）、偏高线（默认 130%）。
- **外部营养 API（可选增强）**：Base URL + API Key 占位；为空则纯本地；「测试连接」按钮 + 失败回退说明。
- **数据管理**：导出 JSON、清空所有数据。
- **关于**：版本、免责声明全文、开源许可说明。

## 3. 核心数据流

```
① 用户输入（饮食：自然语言 / 快捷按钮     运动：自然语言手动输入）
      │  饮食："早餐吃了一碗白米饭、两个鸡蛋，还有一杯豆浆"
      │  运动："跑步 30 分钟" / "快走 1 小时" / "力量训练 40 分钟"
      ▼
② FoodParsingService            ←→      ExerciseParsingService
   ├─ 数量提取：阿拉伯/中文数字 +          ├─ 运动类型匹配：主名 + 别名
   │  量词（碗/个/杯/份/克/两/片/勺）      │  （"跑步"→慢跑/快跑，"举铁"→力量训练）
   ├─ 食物词典：主名 + 别名 + 模糊匹配     ├─ 时长识别：30分钟 / 1小时 / 1.5h / 半小时
   └─ 输出 [ParsedFood]                   └─ 强度默认 .moderate，用户可改
      │                                        │ 解析失败 → 回退"中等强度一般运动"MET=5.0
      ▼  （解析结果永远可人工修正后才入库）    ▼
③ NutritionLookupService                 ExerciseCalorieService
   ├─ 本地食物表（≥50 项）                  kcal = MET × 体重kg × 小时数
   ├─ 外部 API 可选增强（超时 3s 静默失败） 结果存快照（体重/MET/时长/kcal/算法版本）
   └─ 兜底本地表 / 标记未知食物             └─ 始终标注「估算」
      │                                        │
      └──────────────┬─────────────────────────┘
                     ▼
④ DailyIntake（饮食摄入）  +  DailyExerciseBurn（运动消耗）
                     ▼
⑤ DailyEnergyBalance
   ├─ intakeKcal   = 饮食摄入
   ├─ burnKcal     = 运动消耗
   └─ netKcal      = intakeKcal − burnKcal
                     ▼
⑥ AnalysisEngine（双通道，互不干扰）
   ├─ 通道 A｜微量营养素：摄入 vs RDI（**完全不看运动**）
   └─ 通道 B｜能量与宏量：净能量 + 7 天趋势 + 目标
                     ▼
⑦ 建议生成（营养缺口建议 / 运动相关建议 分开输出）
                     ▼
⑧ DailyAnalysis → 今日摘要卡 / 趋势页 / 历史详情
   （底部固定展示免责声明）
```

**关键设计决策 1：运动消耗不回加到推荐摄入量（RDI）。**
活动系数已隐含日常活动水平，若再把额外运动加回 RDI，会诱导「跑了 5 公里所以能吃回去」，与减脂目标相悖。因此：
- **RDI 由「BMR × 日常活动系数 × 目标系数」计算，与当日运动记录无关**；
- 运动消耗只在 **DailyEnergyBalance** 中出现，用于描述「今天是盈余还是缺口」。

**关键设计决策 2：双通道判定，运动不得抵消微量营养素判定。**
`AnalysisEngine` 内部拆成两条互不相通的判定链：
- **通道 A（微量）**：只看饮食摄入 vs 微量 RDI。无论运动多少，钙偏低就是偏低。
- **通道 B（能量/宏量）**：参考净能量与 7 天趋势，给出能量缺口、蛋白质是否足够的判断。
两条通道的结论分别进入建议池，但**通道 B 的任何结论都无权修改通道 A 的状态**。

**关键设计决策 3：建议文案禁止补偿性进食。**
建议生成器内置文案黑名单guard：任何建议中不得出现「因为运动了所以可以多吃/补回来/奖励自己/今天可以放松」等表达。运动相关建议只允许往三个方向写：**补水、蛋白质与恢复、运动与能量缺口的客观说明**。

## 4. 数据模型概览（第 3 步给完整代码）

### 饮食域
| 类型 | 说明 |
|---|---|
| `MealSlotConfig` | 可配置进食时段（id / 名称 / 起始小时 / 结束小时 / 图标 / 排序） |
| `MealEntry` | 一条饮食记录：日期、时段、原始文本、时间戳、来源（时段输入/随手记）、是否已确认 |
| `FoodItem` | 解析后的具体食物：名称、foodID、数量、单位、估算克重、营养快照（冗余，保证历史可复现） |
| `DailyIntake` | 某日饮食摄入聚合（非持久化，实时计算） |

### 运动域（v1.1 新增）
| 类型 | 说明 |
|---|---|
| `ExerciseEntry` | 一条运动记录：**日期**、原始输入文本、时间戳、`[ExerciseItem]` 数组 |
| `ExerciseItem` | 解析后的单项运动：运动类型、时长（分钟）、强度（低/中/高）、MET 值、**估算消耗 kcal**、估算快照（当时体重 / 算法版本） |
| `DailyEnergyBalance` | **饮食摄入 kcal、运动消耗 kcal、净摄入 kcal = 摄入 − 消耗**（非持久化，实时计算） |

### 其他非饮食域
| 类型 | 说明 |
|---|---|
| `WaterEntry` | 饮水：日期、时间、ml |
| `SupplementEntry` | 补充剂：日期、名称、剂量、折算的微量营养素 |
| `BodyMetricEntry` | 身体数据：日期、体重 kg、体脂率 %（选填） |

### 配置与分析
| 类型 | 说明 |
|---|---|
| `UserProfile` | 性别 / 年龄 / 身高 / 体重 / 活动水平 / 目标（**体重同时供 MET 计算使用**） |
| `NutritionProfile` | 计算出的每日推荐摄入量（RDI）：热量 + 三大宏量 + 四项微量 |
| `DailyAnalysis` | 某日分析结论：微量状态 + 宏量状态 + **能量平衡状态** + 中文建议数组 + 免责声明标记 |

## 5. 分析规则

### 通用
- **判定口径**：单日数据仅供参考，**结论以最近 7 天均值 / 趋势为准**。
- **阈值**（可配置，默认）：`< 70% RDI` = 偏低；`70%–130%` = 充足；`> 130%` = 偏高。
- **数据不足**：不足 3 天记录时，只展示数据、不做强结论，提示「记录满 3 天后给出趋势判断」。
- **微量营养素**：用 7 天均值判定，避免单日波动误报。**不受运动影响。**

### 运动消耗估算
- 公式：`kcal = MET × 体重(kg) × 小时数`。
- 本地 MET 表 **≥ 20 种运动 × 3 档强度（低/中/高）**，来自公开 MET 参考值。
- 解析失败 → 回退 `中等强度一般运动 (MET = 5.0)`，UI 明确标注「估算 · 未识别运动类型」。
- **快照冗余**：`ExerciseItem` 保存当时的体重、MET、算法版本，保证历史记录可复现，后续改体重不会篡改历史。

### 能量平衡状态判定
| 目标 | 判据 | 状态 |
|---|---|---|
| 减脂 | 7 天平均净摄入 ≈ TDEE × 0.8 | 缺口合理 |
| 减脂 | 净摄入 > TDEE | 缺口不足 |
| 减脂 | 净摄入 < BMR | 缺口过大（提示谨防代谢适应） |
| 增肌 | 净摄入 ≥ TDEE × 1.1 且蛋白 ≥ 1.6g/kg | 支持增肌 |
| 增肌 | 净摄入 < TDEE | 总能量不足 |
| 维持 | \|净摄入 − TDEE\| / TDEE < 10% | 基本平衡 |

### 建议生成优先级
1. 连续 ≥3 天低于 70% 的**微量**营养素（最优先，给具体食物清单）—— 通道 A，不受运动影响
2. 连续 ≥3 天高于 130% 的宏量/微量（给减量替代方案）
3. **运动相关**：补水、蛋白质与恢复、运动频率与能量缺口说明 —— 通道 B
4. 结构性问题（蛋白供能比过低、纤维长期不足）
5. 习惯养成（饮水不足、夜宵频率高）

- **建议格式**：一句话现状 + 一句话可执行动作 + 具体食物/份量。例：
  > 最近 7 天钙平均摄入 480mg，只有推荐量（800mg）的六成，缺口主要出现在晚餐。明天建议在晚餐加一份 200ml 牛奶或 100g 北豆腐，就能补上约 200mg。
  >
  > 今天记录运动消耗约 285 kcal，属于估算值。运动后建议补充 300–500ml 水，并在下一餐安排约 25g 蛋白质（如 100g 鸡胸肉或 2 个鸡蛋）；注意这不会改变钙摄入偏低的判断，仍需按上面的建议补钙。
- **免责声明**：所有建议、运动消耗与摘要卡片底部必须展示「本 App 数据为估算值，仅供参考，不能替代专业医疗或营养师建议。」
